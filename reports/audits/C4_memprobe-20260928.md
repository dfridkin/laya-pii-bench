# Audit C4: B4 memory probe on the M2 (2026-09-28)

`uv run python scripts/memprobe.py B4 {qs_v2,qs_v1}`: the longest B4 unit among calib/test/holdout
(d0520, 10,965 tokens, truncated to max_len 8,192), 3 calls each, one process per run.

| qs | rows | autocast | calls (s) | device start/end | MPS driver GB | peak RSS GB |
|---|---|---|---|---|---|---|
| qs_v2 | 5 | fp16 (rows >= 5) | 34.9, 50.8, 61.5 | mps / mps | 6.37 | 0.96 |
| qs_v1 | 4 | off (fp32) | 35.7, 58.5, 39.2 | mps / mps | 7.02 | 1.12 |

Result: fits on the 8 GB M2 without laya's CPU fallback, so the D-002 HF fallback is not needed.
Latency varies by up to 1.8x across repeated calls at this size, consistent with memory pressure
(7 GB of 8 GB). B3 (max 3,985 tokens, below B4's worst case) is covered by this bound.
Batched runs are limited to A, B1, B2: batching B3/B4 units would multiply this footprint.
